## 一、最核心的一条：`sourceEntity` **不是产业，是产业的"库存"**

这是整件事里唯一真正难的地方。绕过的三条弯路值得记下来：

| 试法 | 结果 |
|---|---|
| 拿 `cargo.sourceEntity` 去 `get_industry(id)` 查 | **全部 ENTITY_NOT_FOUND** |
| 拿它去 `get_town(id)` 查 | 同样 NOT_FOUND |
| 拿旧产物 `demand-probe.json` 的 id 去对照当前的 `layer-industry.json` | **0 命中** |
| ✅ 拿 `layer-industry.json` 里的 **`stock_list`** 字段去对照 | **97 / 97 全部命中，零误差** |

**结论**：`SIM_CARGO.sourceEntity` 装的是**产业持有的库存实体(stock) id**，
它等于 `SIM_BUILDING.stockList`。所以**必须先把 stock id 翻回产业**，否则前端只能看到一串数字。

### 和你那句补充严丝合缝

你说「货物最终送达城镇、在城镇消失」。数据完全印证：

| 字段 | 真实含义 | 实测数量 |
|---|---|---|
| `cargo.sourceEntity` | 产业的 **stock** —— 反查得产业 | **97 座工厂**在发货 |
| `cargo.targetEntity` | **43 / 563 是产业的 stock** | 厂 → 厂（原料链，可继续追） |
| | **其余 520 个不是** | 厂 → **城镇**（终端消费，货在此消失） |

所以产业链有**两类边**，前端要分开画：**厂→厂**（实线，链继续）／**厂→城镇**（箭头指向城镇，链终止）。

## 二、官方字段（`api.type`，权威依据）

```
**SimCargo**            Additional data for cargo.
  cargoType     int     The cargo type of the cargo (never 0)
  targetEntity  Entity  the entity of the target where the cargo item heads to
  sourceEntity  Entity  the entity of the source where the cargo item came from
  speed         float
  vehicleUsed   bool
  startTime     int     the timestamp when the cargo item was produced
**SimCargoAtTerminal**  Additional data for cargo waiting at the terminal
  edgeId                the edge the cargo is currently using
  place         int
```

三个要留意的点：

1. 官方**只说 source/target 是 `Entity`，没说是建筑** —— 光看文档必然踩上面那个坑。
2. `cargoType` 官方标 **int**，但实际 `tostring` 出来是**可读名**（`FOOD` / `PLASTIC` / `CRUDE`）——
   前端直接拿字符串用，别再转数字。
3. `api.engine.getEntity(edgeId, cargoType)` **不是"按 id 取实体"**（官方定义是
   "Gets one (random) entity from the cargo waiting"）。按 id 取实体要用 `game.interface.getEntity(id)`。

**关联交通怎么来**：

```
货在当前车上 → SIM_ENTITY_AT_VEHICLE.vehicle → 车辆（车辆→线路由前端拼 layer-vehicles）
货在站台等   → SIM_ENTITY_AT_TERMINAL.line   → 线路
货在林段上   → SIM_CARGO_AT_TERMINAL.edgeId  → 具体路段（官方字段，本轮未用）
```

```jsonc
{
  "geometry_kind": "LINK",
  "counts": { "industries": ..., "cargo_scanned": ..., "links": ...,
              "links_to_industry": ..., "links_to_town": ... },
  // 反查表：cargo 里的 source/target 是 stock id，靠这张翻回产业
  "industry_index": [ { "stock": 185808, "industry": 186493 }, ... ],

      "vehicles": [159365], "lines": [224503],
      "first_start_time": ..., "last_start_time": ... }
```

## 五、前端怎么做（设计已定，**代码未写**）

界面行为：**点地图上某个产业 → 高亮它的上下游 + 画出流向线 + 侧栏列明细**。

| 步 | 做法 |
|---|---|
| 1 | 点中的产业 id → 查 `industry_index` 得它的 **stock** |
| 2 | 筛 `links`：`source_industry == 选中` → **下游**；`target_industry == 选中` → **上游** |
| 3 | 线段两端坐标从 `nodes` 取（世界坐标 → 屏幕，用现成的 `P()`） |
| 4 | **厂→厂** 画实线；**厂→城镇** 画箭头收在城镇上（链终止，视觉上区分开） |
| 5 | 线宽/颜色按 `count` 或 `cargo_type` 分；线上标货名 |
| 6 | 高亮相关的产业与城镇节点 |
| 7 | 侧栏列：上下游清单（对象 · 货物 · 流量 · 走哪条线 · 车上/候货各多少） |

**性能**：这一层是**按需绘制**（只在选中时画那几十条线），
而且线画在 SVG 世界层里、拖动零重算 —— 跟你之前关心的开销问题不冲突。
