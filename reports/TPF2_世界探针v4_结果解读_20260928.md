## 〇、三条核心结论

### 1. 🔴 「公路图层」几乎零成本 —— `BASE_EDGE` 是公路+铁路的统一几何表

这是本次最重要的发现，它直接改写任务规划。

```
BASE_EDGE        10,444 条  ← 统一表（字段完全相同）
├── BASE_EDGE_TRACK   5,182   track=true   streetType=''
└── BASE_EDGE_STREET  5,262   track=false  streetType='standard/country_large_new.lua'
    5182 + 5262 = 10444  ✅ 数量守恒，无遗漏
```

`BASE_EDGE` 的完整字段（v4 实测）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 边 ID |
| `node0` / `node1` | number | 两端节点 ID |
| `node0pos` / `node1pos` | table[3] | **端点世界坐标 {x,y,z}** |
| `node0tangent` / `node1tangent` | table[3] | **端点切线**（做法和铁路完全一样） |
| `track` | boolean | **true=铁路，false=公路** |
| `streetType` | string | 道路类型文件名（如 `standard/country_large_new.lua`）→ 可按类型分级着色 |
| `hasBus` / `hasTram` | boolean | 是否跑公交/有轨电车 |

**含义**：现有的 `rail_network.lua` 已经在读 `BASE_EDGE`（`node0/node1/tangent0/tangent1`）—— 公路网只差一个 `track` 分流。不是"照它改一个采集器"，而是**同一个采集器里多吐一份数据**。

### 2. 🔴 `api.engine.system` 的 31 个系统是拿数据的正路 —— 比遍历便宜一到两个数量级

v4 首次把 31 个系统的方法表全枚举出来。其中**直接对应图层**的：

| 系统 | 方法 | 能干什么 |
|---|---|---|
| `riverSystem` | `getWaterMeshEntities` | **水体图层**的正路（`WATER_MESH` 是列表型，不能当实体取） |
| `streetSystem` | `getNode2StreetEdgeMap` / `getNode2TrackEdgeMap` / `getEdgeObject2EdgeMap` / `getNode2SegmentMap` | 公路网与铁路网**分别**的图结构，还能拿到路段划分 |
| `townBuildingSystem` | `getTown2BuildingMap` / `getBuilding` / `getCargoSupplyAndLimit` / `getLandUsePersonCapacities` / `getPersonCapacity2townBuildingMap` | **城镇建筑图层** + 人口容量 + 供需 |
| `parcelSystem` | `getParcelData` / `getSegment2ParcelData` | **地块图层**（`PARCEL` 4 万那个量级，不用硬遍历） |
| `octreeSystem` | `findIntersectingEntities` | **空间查询 —— 按包围盒取子集**，解决一切大数据量问题 |
| `catchmentAreaSystem` | `getStation2edgesMap` / `getStation2stationsAndDistancesMap` | 车站辐射范围（画"服务区"用） |
| `stationSystem` | 10 个方法：`getStation2TownMap` / `getTown2StationsMap` / `getStationTerminalsForPersonEdge` … | 车站与城镇/站台的全套映射 |
| `transportVehicleSystem` | 10 个方法：`getLineVehicles` / `getLine2VehicleMap` / `getVehiclesWithState` / `getNoPathVehicles` | 按线路取车、按状态取车 |
| `lineSystem` | 9 个方法：`getLineStops` / `getProblemLines` / `getLinesForWaypoint` | 线路停站、**问题线路** |
| `signalSystem` | `getSignal` | 信号机（比 `SIGNAL_LIST` 更直接） |
| `tpNetLinkSystem` | `getEdgeId2linkEntities` / `getLinkEntities` | `TP_NET_LINK` 1,085 条（列表型）的正路 |
| `simPersonSystem` | `getSimPersonsMovingForTransportNetwork` / `getSimPersonsForLine` | **移动中的乘客**（可做客流可视化） |
| `simEntityAtVehicleSystem` | `getVehicle2Cargo2SimEntitesMap` / `getFare` | 车上实际载着什么（货/人） |
| `runwaySystem` | `getLandingNodeIdMap` / `getTakeoffNodeIdMap` | 起降点（航空） |
| `stockListSystem` | `getCargoType2stockList2sourceAndCount` / `getSources` | 货源与库存 |
| `transportHistorySystem` | `getStationTransportHistoryReferences` / `getTargetTransportHistoryReferences` | 运输历史 |
| `railRoadCrossingSystem` | `getRailroadCrossingForEdge` / `getRailroadCrossingForNode` | 平交道口 |

**含义**：新增图层不必再"整表遍历 + 猜字段"，优先找对应系统方法。

### 3. `game.interface.getEntity(id)` 的聚合表**确实可枚举**（32/41 组件拿到 7–17 个键）

v3 的最大缺口（字段名）就此关闭。但有一条**必须记住的陷阱**：

| 组件 | getEntity 返回的 type | 说明 |
|---|---|---|
| `BASE_EDGE` / `BASE_EDGE_TRACK` / `BASE_EDGE_STREET` | `BASE_EDGE` ✅ | 一致 |
| `BASE_NODE` | `BASE_NODE` ✅ | |
| `STATION` / `STATION_GROUP` / `TOWN` / `LINE` / `PLAYER` | 一致 ✅ | |
| `TRANSPORT_VEHICLE` / `TRAIN` / `SHIP` / `AIRCRAFT` | `VEHICLE` ✅ | 四个车种返回同一结构，靠 `carrier` 分（RAIL/WATER/AIR） |
| `SIM_BUILDING` / `TOWN_BUILDING` / `CONSTRUCTION` | 一致 ✅ | |
| **`TICK_EPOCH`** | 返回 `BASE_EDGE` ❌ | **附属组件** |
| **`PERSON_CAPACITY`** | 返回 `CONSTRUCTION` ❌ | 附属组件 |
| **`ACCOUNT`** | 返回 `LINE` ❌ | 附属组件 |
| **`NAME`** | 返回 `SIM_PERSON` ❌ | 附属组件 |
| **`TRANSPORT_NETWORK`** | 返回 `BASE_NODE` ❌ | 附属组件 |
| **`ROAD_VEHICLE` / `MOVE_PATH`** | 返回 `SIM_PERSON` ❌ | `ROAD_VEHICLE` 不是"卡车"，它的名字骗人 |

**规矩**：`getEntity(id)` 回答的是「这个实体**是什么**」，不是「我要的那个组件」。**只对"真实体类"组件有效**；附属组件必须走 `api.engine.getComponent`。

**列表型组件（getEntity 返回 `nil`，共 9 个）**：`WATER_MESH`、`BRIDGE`、`TERRAIN_TILE`、`LOT_LIST`、`TP_NET_LINK`、`RAIL_VEHICLE`、`TOWN_CONNECTION`、`BASE_PARALLEL_STRIP`、`MODEL_INSTANCE_LIST`
→ 这些必须走 `api.engine.system.*` 或从持有它们的实体上取。

## 三、对任务规划的修正

### 阶段 2 从「公路网」扩成「公路 + 亮层」

因为公路几乎免费，第一批可以顺带把**成本极低且直接有用**的几个一起做掉：

| 批次 | 图层 | 数据源 | 一句话 |
|---|---|---|---|
| 2.1 | **公路网** | `BASE_EDGE.track=false` | 复用铁路采集器，加分流 + `streetType` 分级着色 |
| 2.2 | **产业** | `SIM_BUILDING` 131 | 点 + 名称 + 生产/消耗/发运量 |
| 2.3 | **车辆分车种** | `TRANSPORT_VEHICLE.carrier` | 现有全被画成同一种；现在能分铁路/公路/水运/航空四色 |

### 新增建议：先做「图层地基」再铺图层

三位调研子 Agent 独立指出同一个风险：**所有图层必须共用同一套 `bounds` 和 tile 网格原点**，否则叠加会整体错位（前端投影完全由 manifest 的 `bounds` 决定）。所以阶段 1 的"图层契约"里必须钉死：

1. 全图层共用一份**全局 `bounds`**（取铁路网的 bounds，或取 `TERRAIN` 的 `size`）
2. tile 网格原点与尺寸**全局统一**（2,000 m），否则 `tile-0_0` 在不同图层指向不同区域
3. 每层各自带 `detail_load_threshold_m`（大图层要更大的阈值，否则一开就拉爆视口）

### 其它已确认的工程约束（来自调研）

- **输出目录必须是项目目录**：`station_preview.py` 会**删除不匹配的 `station-*.json`** → 多图层共用 `station-previews/` 会误删铁路缓存，新图层必须各自独立输出目录
- **前端分块状态是单例**（`desiredTileKeys` / `loadedTiles` / `pendingTiles` / `window.RAIL_NETWORK_TILES`），加图层前必须泛化成 `layers{...}`
- **mod 沙箱没有 `os.rename` / `os.remove`** → 不能用"写临时文件再改名"做原子替换；`io.open` 也不会自建目录，`bridge/layers/` 得由外部预建
- **`write_json` 只有两份，都是 local** → 新模块要么自带一份，要么抽 `collectors/bridge_io.lua`
