## 一、承载人数是怎么算出来的（源码为证）

**车站的"承载人数"不是车站自带的，而是它**已装模块**之和。**

`res/scripts/modulesutil.lua:19`：

```lua
function modulesutil.getStationPoolCapacities(modules, result)
    local passCap = 0
    local cargoCap = 0
    for num, slot in pairs(result.slots) do
        local constructionModule = modules[slot.id]
        if constructionModule and not (constructionModule.metadata.moreCapacity == nil) then
            if not (constructionModule.metadata.moreCapacity.cargo == nil) then
                cargoCap = cargoCap + constructionModule.metadata.moreCapacity.cargo
            end
            if not (constructionModule.metadata.moreCapacity.passenger == nil) then
                passCap = passCap + constructionModule.metadata.moreCapacity.passenger
            end
        end
    end
    return passCap, cargoCap
end
```

→ **车站承载人数 = Σ 该站所有模块的 `metadata.moreCapacity.passenger`**（货运站取 `cargo`）。
原版 `station/rail/modular_station/modular_station.con` 把这个和写进 `station.pool.moreCapacity`。
**站台、雨棚、楼梯、轨道模块一律不提供容量**——容量全部来自「主站房 / 侧房」这两类建筑模块。

> 那要么容量不是硬上限、要么这 622 人的候车归属在站内另一个带了建筑的站群里 —— 这条需要你在游戏里看一眼 Hanoi 的车站窗口确认。

## 四、怎么算出「某个具体车站」的承载人数

公式已确定：**Σ（该站已装建筑模块的承载值）**。举几个组合：

| 组合 | 承载人数 |
|---|---|
| 1×大主站房 C 期 | 200 |
| 1×大主站房 C 期 + 2×大侧房 C 期 | 200 + 150×2 = **500** |
| 1×中主站房 C 期 + 1×中侧房 C 期 | 50 + 40 = **90** |
| 1×小主站房 A 期 | 20 |

**还缺的一环**：**"某站实际装了哪些模块"这份清单读不到**：
- 引擎 API：`STATION_GROUP.capacity` 返回 `nil`，车站实体的可读字段只有 `itemsLoaded / itemsUnloaded / cargoWaiting / stations / position / name`
- 存档：模块条目能搜到（`name = station/rail/modular_station/main_building_2_era_c.module`，共 204 条），
  但与车站的对应关系无法可靠归位（车站名在存档的另一段，实体 ID 也不在模块条目附近 —— 两种关联法都试过，0 命中）

→ **两条可行的补法**（任一即可）：
1. 你在游戏里打开这几个站的车站窗口，把「容量」数字读给我（一次 1 分钟）；
2. 或者告诉我某站装了什么（例如「广州北站 = 大主站房 C + 2 个大侧房 C」），我按上表直接算。

拿到数字后，就能把 JY 调整方案的验收标准写成硬的：**候车人数 ≤ 站点承载人数**。
