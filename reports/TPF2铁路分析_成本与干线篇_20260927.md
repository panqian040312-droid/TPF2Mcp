# TPF2 铁路运营分析（成本篇 + 干线车流篇）

生成：2026-09-27 ｜ 存档 `world-v1-3be64aa7d6888335915d90b1`
本篇接在《运量优先版》之后：那一篇解决「配车 vs 运量」，本篇解决你提的两条
——**零成本车辆只算需求**、**干线车流量与堵车风险**。

---

## 一、车辆成本怎么读（口径先说明）

游戏 API 读不到成本：`TRANSPORT_HISTORY` 的 revenue / profit / cost / maintenance 字段返回 **nil**
（探针实测，项目文档也标为 UNAVAILABLE）。**成本只能从游戏与 Mod 的模型定义文件里读**：

模型文件（`res/models/model/**.mdl`）的 metadata 里有：

```lua
cost        = { price = …, priceScale = … }
maintenance = { lifespan = …, runningCosts = …, runningCostScale = … }
```

判定规则（**实测确认，不是推测**）：

| 写法 | 含义 |
|---|---|
| `price = -1` | **游戏自动定价** —— 原版车也是这样（我抽查了原版 `china_df4b_v2.mdl`，同样是 -1），不是免费 |
| `price = 0` / `priceScale = 0` | **零购置成本**（真免费车） |
| `runningCostScale = 1` | 运行成本按标准计 |
| `runningCostScale < 1` | **运行成本打折** |
| `runningCostScale = 0` | 运行成本为零 |

⚠️ 自动定价的车，具体金额**不写在文件里**（游戏运行时算），所以「这辆车花了多少钱」读不到；
能读到的是「是否被显式设为免费/打折」。

## 二、本存档的成本判定结果

扫描了铁路车辆用到的全部 65 个模型（覆盖原版 + 10 个创意工坊车辆 Mod）：

| 类别 | 车辆数 | 所属线路 | 模型证据 |
|---|---|---|---|
| **零购置成本** | 1 | JI线路 | `vehicle/train/l3/*.mdl` → `price = 0, priceScale = 0`（上海地铁 l3 车型，mod 2819774551） |
| **运行成本 6 折** | 16 | 成郑云轨内环、成郑云轨外环、津京空轨内环、津京空轨外环（各 4 辆） | `vehicle/waggon/SuspendedMonorail/Sus_Mon_*.mdl` → `runningCostScale = 0.6` |
| 运行成本为零 | 0 | — | 没有任何模型把运行成本倍率设为 0 |
| 自动定价（普通） | 其余 55 辆 | 其余 31 条线 | `price = -1` |

**对你要求的落地**：这 17 辆特殊成本车所处的 5 条线（JI线路 + 4 条云轨/空轨线），
调车时**先看运量是否满足需求，成本不是约束**；其余 31 条线才需要按「每车年运量」做成本核算。

### 2.1 更正：复兴号 / 和谐号 **不是**零成本（首版解析有漏）

首版解析只认字面数字，漏掉了这两类写法，现已修正：

```lua
local trainCostPrice    = 6.142857143e+06   -- 变量定义在文件头部
local trainRunningCosts = 6.142857143e+03
cost        = { price = trainCostPrice,    priceScale = 1 }
maintenance = { lifespan = 36525, runningCosts = trainRunningCosts, runningCostScale = 1 }
```

| 车型（Mod） | price / 节 | runningCosts / 节·年 | 判定 |
|---|---|---|---|
| **复兴号 CR400AF-0208 / 0207（含 CRH 和谐号涂装版）** mod 3374213837 | **6,142,857.143** | **6,142.857143** | **显式定价（最贵一档）** |
| 复兴号 CR400BF-C  mod 3015141575 | -1 | -1 | 游戏自动定价（非 0） |
| 复兴号 CR200J（绿巨人） mod 3037553623 | -1 | -1 | 游戏自动定价（非 0） |
| 和谐号 CRH | — | — | 本机没有独立和谐号车辆 mod；它是 CR400AF-0207 的一个涂装版本（mod 字符串写明 "CRH version"），成本同 CR400AF |

**交叉验证**：CR400AF 是 8 节编组 → 6,142,857.143 × 8 = 49,142,857（文件值），
按该 mod 自述的折算关系「1 单位 = 0.5 美元」得 **≈ 24,571,428**，
与该 mod 说明字符串里写的 **"Purchase cost: about $24,600,000 in game"** 一致 —— 解析正确。

> ⚠️ 那条说明的后半句 `This mod was never charged and only published on Steam Workshop…`
> 意思是**作者从没向玩家收过费（mod 本身免费下载）**，**不是**游戏内车辆运营费用为 0。
> 这大概是"复兴号成本为 0"这个印象的来源。

**唯一能让车辆真正零成本**的机制是原版脚本 Mod `urbangames_no_costs_1`
（内容只有一行 `game.config.noCosts = true`，全局关掉所有购置与运营费用）。
它确实装在游戏 `mods/` 目录里，但**当前存档的启用列表（`settings.lua` 的 activeMods，33 个创意工坊 Mod）里没有它**，
全工坊 73 个 Mod 也没有任何一个自带脚本关闭成本。所以本存档的成本是**生效**的。

### 2.2 游戏内财务图证据：复兴号营运成本 ≈ 0 是**显示舍入**，实质极低

用户在游戏内打开 **列车12**（= 复兴号 CR400AF-0208，8 节，JY客运）的「财务」页：
收入柱在 **20–60 M** 之间，而**营运成本那条红线贴着 0 看不见**。

逐列核算（文件值 × 0.5 = 游戏内美元）：

| 列车 | 线路 | 节数 | 整列购置（≈$） | 整列运行费/期（≈$） |
|---|---|---|---|---|
| 列车41 | 京广客运 | **16**（重联） | 98,285,714 → **$49,142,857** | 98,286 → $49,143 |
| 列车6 / 12 / 14 | JY客运 | 8 | 49,142,857 → **$24,571,429** | 49,143 → **$24,571** |

- 复兴号每节运行费仅 **6,142.857 文件值（≈$3,071）**，8 节合计 ≈ **$24,571 / 期**；
- 财务图纵轴以**百万**为刻度 → $24,571 = **0.0246 M**，四舍五入后显示成 **0.0 M** ——
  这就是"营运成本 0"的来源，**不是定义里写了 0**；
- 相对其收入（几千万量级），运行成本占比约 **0.08%**。所以**在决策意义上你是对的**：
  复兴号属于"运营成本可忽略"的资产。

**成本结构对比（每节运行费）**：复兴号 CR400AF **6,142.86** ＜ 货运型 qingguiCO **21,600**
—— 复兴号的运行费只有货运车的 **28%**。

### 2.3 这对动作清单的修正

| 事项 | 修正后的判断 |
|---|---|
| 加复兴号车 | 运营成本可忽略，约束主要是**购置价**：一列 8 节约 **$24.57M**，京广客运那列 16 节重联约 **$49.14M** |
| 京广客运（每车年运量 2,637，铁路最高档） | 已用 16 节重联但**只有 1 列**、班次 18 分钟 → 加一列的资金约 $49M，按其收入量级回本较快，值得做 |
| JY客运（每车年运量 2,118） | 已有 3 列 8 节复兴号 + 1 列 CR400BF-C，运量高，加车同样以购置价为主要约束 |
| 货运闲置线减车 | 省下的是实打实的运行费：Yo木材 5 列 ≈ **$108,000/期**、泉州钢铁 3 列 ≈ **$32,400/期**、咸阳石化 4 列 ≈ **$129,600/期**，合计约 **$270,000/期**，只换回 5.4% 的铁路运量 |

### 2.4 另一档显式定价车：货运型 `qingguiCO`

多条货运线（Yo木材、泉州钢铁、咸阳石化、IS炼钢、长沙板材、线路 11/12、中山原油2、咸阳原油1、Han石化、咸阳煤炭/矿物空中轨道）
用的是 `vehicle/train/qingguiCO.mdl`，**显式定价 2,030,000/节 + 运行费 21,600/节·年**
（每节运行费是复兴号的 3.5 倍）。

这给"减车"提供了具体金额：

| 线路 | 车数 | 运行费/年（每车 1 节计） | 运量占比 |
|---|---|---|---|
| Yo木材 | 5 | ≈ 10.8 万 | 1.3% |
| 泉州钢铁 | 3 | ≈ 6.5 万 | 0.6% |
| 咸阳石化 | 4 | ≈ 8.6 万 | 3.4% |
| **合计** | **12** | **≈ 25.9 万/年** | **5.4%** |

12 辆车每年约 26 万的运行费，只换回 5.4% 的铁路运量 —— 而且其中 Yo木材+泉州钢铁
还在共用区间 `B00220` 上互相挡路。

值得注意的一点：这 4 条云轨/空轨线在运量表里正好偏中下
（每车年运量 1,178–1,780，中位数 1,503）——**它们不是"该减车"的重点**，
因为成本本来就只有 6 折，减车的收益远小于普通车。真正的减车对象见第四节。

## 三、干线车流量（实测，非估算）

方法：对 `/api/live` 连续采样 **60 帧 / 182 秒**（间隔 3 秒，每帧 72 辆车），
记录每帧每辆车的轨道边与闭塞区间，再统计并发与共用情况。

### 3.1 共用轨道（干线段）

实测被两条以上铁路线车辆走过的**共用轨道边 19 个**，涉及 5 组线路对：

| 线路对 | 共用段数 | 合计理论车流 |
|---|---|---|
| 广州燃料铁路 + 中山货物铁路 | **6** | **23.8 列/小时** |
| JI线路 + JY客运 | 5 | 19.4 列/小时 |
| 咸阳煤炭空中轨道 + 咸阳矿物空中轨道 | 5 | 18.0 列/小时 |
| JY客运 + 京广客运 | 2 | 12.3 列/小时 |
| 线路 9 + 广钢原料 | 1 | 20.9 列/小时 |

理论车流 = Σ(3600 ÷ 该线班次)。23.8 列/小时是全网共用段的最高水平。

### 3.2 跨线争用的闭塞区间（9 个）

```
B00773 / B01446   JY客运 + 京广客运
B01466 / B00793   JI线路 + JY客运
B00220            Yo木材 + 泉州钢铁
B00492            咸阳煤炭空中轨道 + 咸阳矿物空中轨道
B00654 / B01264 / B01265   广州燃料铁路 + 中山货物铁路
```

### 3.3 真正堵住的地方：只有 1 个

采样期间**唯一出现"同一闭塞区间同时有两列车"的是 `B00220`**：
占用帧比例 **83.3%**，涉及 **Yo木材 + 泉州钢铁**，最大并发 2 列。

也就是说：**全网目前只有这一处在互相等车**。而这两条线正是运量分析里被判
「运力闲置」的线（每车年运量 250 / 211，是下四分位以下）。

> 结论很直接：给 Yo木材 / 泉州钢铁 加车**不会提高运量，只会让这个共用区间更堵**。
> 减车反而同时解决"运量低"和"互相挡路"两个问题。

### 3.4 全网层面

| 指标 | 数值 | 含义 |
|---|---|---|
| 闭塞区间总数 / 当时占用 | 1,478 / 71–72（**4.9%**） | 大面上远未饱和 |
| 采样覆盖区间中出现并发的 | 1 / 381 | 冲突是局部的，不是全局的 |
| 运行图相位冲突（1 小时视窗） | 386 → **311 次**（相位优化后） | 车流层面的冲突量级，加车前要看它集中在哪 |
| 信号机 | 765 个（2.56 个/km） | 闭塞划分可用 |

⚠️ 读表注意：**单车线路的区间占用率天然≈100%**（那辆车一直停在某个区间里），
不能当成拥堵指标；只有「并发 ≥2」和「跨线共用」才有判断价值。

## 四、修正后的动作清单（成本 × 运量 × 干线 三者合并）

| 优先级 | 动作 | 对象 | 依据 |
|---|---|---|---|
| **1** | **减车** | Yo木材（5 车，每车年运量 250）、泉州钢铁（3 车，211） | 运量下四分位以下 **且** 这两条线共用的 B00220 已出现并发（83% 占用）—— 减车同时降本、解堵 |
| 1 | **减车** | 咸阳石化（4 车，844） | 运量偏低，车辆按自动定价（普通成本），减车直接降本 |
| **2** | **加车** | IS炼钢（1→2）、中山原油2、线路 12、长沙板材、LZ石化、Jed石化 | 每车年运量 1,846–3,712（上四分位以上），且**不涉及任何共用干线段**，加车无堵车风险 |
| 2 | **加车（先查共用段）** | 京广客运 | 每车年运量 2,637、班次 18 分钟；但它在 B00773/B01446 与 JY客运 共用——加车前先确认那两段的越行条件 |
| 3 | **按需判断，成本不设限** | JI线路（1 辆零购置成本）、成郑云轨内/外环、津京空轨内/外环（运行成本 6 折） | 成本豁免线，只看运量是否满足；注意 JI线路 与 JY客运 共用 5 段 |
| 4 | **加车前必查** | 广州燃料铁路、中山货物铁路 | 互相共用 6 段、23.8 列/小时（全网最高共用负荷），是目前最接近拥堵的组合 |
| 5 | **补联络线形成回路** | 主干链（节点 118880↔119027 一带） | 44.6% 的轨道边是割边，主干一断全断 |

## 五、结论三句话

1. **成本只有在非豁免线才是约束**：17 辆车（5 条线）成本特殊，其中 4 条云轨/空轨线是 6 折，
   减车的收益被成本折扣抵消，不该优先动。
2. **全网只有 1 处堵点**（Yo木材+泉州钢铁 共用区间 B00220），而它恰好是运量最低的两条线——
   加车不但没用，还会加剧；减车是双赢。
3. **加车优先给不共用干线的低配车高运量线**（IS炼钢、中山原油2、线路12、长沙板材等），
   京广客运虽然运量高，但要先确认与 JY客运 共用段的通过能力。

## 七、数据边界

- 成本：只能判定"是否显式免费/打折"，**读不到自动定价车的具体金额**；分线收入/利润不可得。
- 干线：采样窗口 182 秒，覆盖 381/1478 个闭塞区间、1196/9765 条轨道边；
  未覆盖区段不代表没有共用，只代表这段时间没有车经过。
- 需求：车站候客数据仍为 `UNKNOWN`（Mod 为规避游戏原生崩溃已禁用采样），
  "需求是否被满足"是**用运量与配车比推断**的，不是直接观测。
