## 三、核心问题：咽喉诊断（多轮纠错后的最终版，勿重蹈旧结论）

**走廊**：`Omsk → Zhengzhou → Kolkata → Foshan`

**🔴 这不是单线，是客货分离的复线**（早期误判成"7.91 km 单线咽喉"，已被用户质疑推翻）：

```
Omsk ──── 货运轨道 7.90 km ──── Foshan    5 条货运线在用，并发 2.94
  ╲                                         两条几何平行（边中点间距中位 30.7 m）
   ╲─── 客运轨道 9.03 km ────╱             DMAOZK 75% + ZKS 15%，并发 2.70
```

- 两条轨道**共享 0 条边，只共享起终点 2 个节点**（Omsk 货运站台 `240679`、Foshan 货运站台 `259119`）
- **🔴 真正的根因：两条轨道各自都在双向混跑**
  | | 朝 Foshan | 朝 Omsk | 同一时刻两个方向都有车 |
  |---|---|---|---|
  | 货运轨道 | 5 辆 | 3 辆 | **233/260 = 90%** |
  | 客运轨道 | 5 辆 | 2 辆 | 64/260 = 25% |
- **拥堵系数 2.05×**：实测通过时间 **364.8 s** vs 逐边限速理论 **178.3 s**
- **🔴 中间 7.9 km 零跨线道岔**（`check_crossovers.py` 穷举）：跨线边总共只有 4 条，全在两端站台处
  → 列车从站台选定 A 或 B 后必须跑完 7.9 km 才能出来，**中途绝对不能换线避让**
  → 交会只能在 Zhengzhou(里程 3.07) / Kolkata(5.64) 两个中间站内干等 → 而货运轨 90% 时间有对向车 → 几乎每趟都要等

**最惨车辆**：171919（佛山原木运输）区间滞留 17%、最长连续 37 秒。

**限速不是瓶颈**：混铺 7 种轨道 mod（119/158/248/299/385 km/h），慢段（160）只在 Zhengzhou→Kolkata 间约 1.2 km，而货运车顶速就是 160。

## 五、机制认知（实测得出，别重新论证）

1. **列车走哪条轨道 = 由它停哪个 `station_group` 决定**（`verify_station_binding.py` 验证）
   - 同名的客/货是彼此独立的 station_group：Omsk = 158519(客运)/161643(货运)；Foshan = 238799/186921；Zhengzhou = 158962/159765；Kolkata = 159263/159040
   - 用户的客货分离本来就是用这个机制实现的
   - **上限**：station_group 绑定做不到「方向分离」（同一条线往返都停同一站组）→ 单条线内部多辆车的双向交会依然存在（佛山原木 3 辆、郑州转运 3 辆）。要归零只能每轨 1 辆车。
2. **线路路径是静态的**（同一条线的所有车都走同一条轨，实测 5 条货运线的车全在 A 轨）
   → 引擎按最短路自动算，**玩家不能直接指定** → 强制走某条轨 = 在停站序列里插路径牌
3. **双线的正确用法是按方向分**（一条东行一条西行，零交会）；按客货分（现状）会让每条都双向混跑
4. **站台压力实测（`analyze_station_pressure.py`）**：全档**没有任何车站出现站台排队**（峰值 1–2 辆 vs 站台 2–5 个）；Omsk 货运站台利用率仅 0.33 → **扩站台帮不上忙**（且 Omsk 地形受限无法扩）
5. **4 倍速实测只有 1.7–2.1 倍**：`speed_multiplier=4.0` 设置生效，但实际 `game_clock.rate` 只有 1.7–2.1（多次 0.94/2.63/2.64/1.63/0.98）→ **设 4 倍速实际只快约 70%，CPU 跑不满**（用户容易误判成"改了没效果"，要提醒）
6. 引擎 tick 固定游戏时间（**200 ms/tick**）→ **倍速不降模拟精度**
7. mod 侧采样稳定在**每 2.01–2.02 墙上秒一帧** → 采样脚本间隔要 ≥2 s，否则一半是重复帧

## 六、⚠ 判据陷阱（踩过的坑，别再犯）

1. **"被 ≥2 线共用的边"构成的走廊会漏掉平行轨道** → 别再拿它判单线/复线。判单线必须从**站台组合穷举**或**两条路径的几何平行性**入手。
2. **"停靠线路数 > 站台数" 不是站台瓶颈判据** → 必须看实测的站内同时占用车辆数。
3. **等待时长有哨兵值**：`request_time = 0` 的实体等待 = 整个游戏时长 → `p90 == max == 同值` 即为伪影，**看中位数**才是主流人群。
   本档实例：RABSQ 候车 1237 / p90=max=7590 分，但**中位仅 7.4 分** → 主流健康，长尾是伪影。
4. **时钟比例动态**（挂钟/游戏在 0.43–2.64 间剧烈变化）→ **一律现读 `simulation.deltas.{game_time, wall_seconds}`**，不许用固定常数。
5. **单次快照 + 单一指标不作结论** → 必须「实载 + 候车 + 等待中位」三者同看。
6. **客货判据不同（用户钦定）**：货运只看「队列不涨 + 车在取货」；客运看「实载 + 候车 + 等待中位」。
