# TPF2 机场站场结构解析（2026-09-30）

> 承接《交接 4》第七节待办 2／3：**机场 slotId 只有一维序号、不含坐标 → 结构画不出**。
> 本文把这条**干完**：给出可用的坐标公式、用真实存档做了三重验证、并说明剩下的工程量。

---

## 零、一句话

**机场的 slotId 不是"一维序号"，是「按模块类型分段的基址 + 连续序号 k」，而每个 k 的坐标在 `.con` 里是显式写死的常数公式。**
公式已按游戏本体源码还原，用存档里两座真实机场验证：**11 个模块全部命中**、推导几何与引擎给的包围盒**三面吻合到 0.0 m**。

wiki 里对应的答案就是 `modding:modularconstructions` 那一页 —— 它写明槽位几何在构建期的
`result.slots[]`（`id` / `type` / **`transf`** / `spacing` / `shape` / `height`），而**不留在 `CONSTRUCTION` 组件上**。
⇒ 想拿到几何只有两条路：**① 照 `.con` 复现公式**（本文走的路，纯静态、不用重启游戏）；② 运行时读别的组件（见第六节）。

## 一、wiki 里的对应章节（出处）

| 内容 | 出处 |
|---|---|
| 模块/槽位模型的官方定义：`modules[slotId] = {metadata, name, updateScript, variant}` | `modding:modularconstructions`（官方 wiki，已收进专家包） |
| **槽位几何**：`result.slots[] = { id, type, transf, spacing, shape, height }`，`transf` = **相对建筑原点的变换矩阵** | 同上，"Return Data Struct" 一节 |
| `spacing = {-x, x, -y, y}`、`shape` = 0方/1三角/2横矩形/3纵矩形、`height` | 同上 |
| 机场特有：`result.runways` 给出跑道（`LANDING` / `TAKEOFF` + 节点 + 边） | 同上 |
| 官方给的 slotId 样例（就是**小机场**）：`[10001000] main_building` / `[10002004] hangar` / `[10070002] passenger_terminal` | 同上，"Construction Templates" 一节 |

**关键一句（官方原文）**：*"The `result.slots` block is a list of all currently existing slots… `transf` is the position relative to the construction origin as a transformation matrix."*
—— 所以**坐标是存在的、是官方定义的**，只是**不在运行时组件里**，要自己算。

`.con` 打包在 `<游戏本体>\res\construction\construction.zip` 里（**`grep -r` 搜不到，要用 Python `zipfile` 读**）：

| 文件 | 对应建筑 | 解锁年 | 本存档 |

## 三、大机场 `airport.con` 的 slotId 与坐标公式

### 3.1 基址（抄自 `.con` 第 11–23 行）

| 类型 | 组 1 基址 | 组 2 基址 | 说明 |
|---|---|---|---|
| `main_building` | **1000** | 1500 | 主楼 |
| `hangar` | **2000** | 2500 | 机库 |
| `tower` | 4000 | — | **代码里被注释掉了，存档中不会出现** |
| `cargo_stock` | 5000 | — | 同上 |
| `2nd_runway` | **8000** | — | 第二跑道（单例槽位） |
| `terminal_B` | **8050** | — | B 区站台，仅在有第二跑道时存在 |
| `landing` | **9000** | — | 降落方向灯，4 个槽位（9000/9001/9002/9003） |
| `terminal`（客） | **70000** | 75000 | 客站台 |
| `terminal_cargo`（货） | **80000** | 85000 | 货站台 |

### 3.2 常量（`.con` 第 252–277 行）

```
taxiwayStartX = -250   taxiwayEndX = 250   slotDistance = 20   numSlots = 25
taxiDistance  = 60     runway1YCoord = 90  runway2YCoord = 149
mainBuildingSize = {120,110}  hangarSize = {80,110}  terminalSize = {60,110}  slotHeight = 110
modules1BackY = 90 - 60 - 30 - 110 = -110      ← 组 1 模块行「外侧边」
modules2BackY = 149 + 60 + 30 + 110 = +349     ← 组 2 模块行「外侧边」
```

### 3.3 坐标

**① 模块行（`MakeSlots`）** —— 交给函数的是 `*_BackY`，模块中心 = `BackY ± 尺寸/2`：

| 类型 | k 取值 | 局部坐标 (x, y, z) | 朝向 |
|---|---|---|---|
| `main_building` | 0…25 | `(20k − 250, **−55**, 0)` | 组1 0° / 组2 180° |
| `hangar` | 0…25（**跳过 k=1、24**） | `(20k − 250, −55, 0)` | 同上 |
| `terminal` | **2…22** | `(20k − 240, −55, 0)` | 同上 |
| `terminal_cargo` | **2…22** | `(20k − 240, −55, 0)` | 同上 |

> 组 2（第二跑道一侧）y 换成 **+294**、朝向 180°，x 公式不变。
> 组 2 只在**同时有第二跑道和第二滑行道**（也就是 `terminal_B` 槽位非空）时创建。

**② 单例槽位**：

| slotId | 类型 | 局部坐标 | 朝向 | 槽位盒（x半宽 × y半高） |
|---|---|---|---|---|
| 8000 | `2nd_runway` | `(0, 149, 0)` | 0° | 270 × 30 |
| 8050 | `terminal_B` | `(0, 209, 0)` | 0° | 250 × 20 |
| 9000 | `landing` | `(285, 90, 0)` | 0° | 40 × 15 |
| 9001 | `landing` | `(−285, 90, 0)` | **180°** | 40 × 15 |
| 9002 | `landing` | `(−285, 149, 0)` | **180°** | 40 × 15 |
| 9003 | `landing` | `(285, 149, 0)` | 0° | 40 × 15 |

**③ 场地几何**（画底图用）：地面矩形 `x∈[−290,290]`、`y∈[0,239]`；
跑道 1 `y=90`、跑道 2 `y=149`（都是 `x∈[−280,280]`）；滑行道 `y=30`（跑道1侧）与 `y=209`（跑道2侧）。

### 3.4 局部坐标 → 世界坐标

`CONSTRUCTION.transf` 是 **列主序** `Mat4f`（元素 0/1/2、4/5/6、8/9/10 是三个轴在世界里的像，12/13/14 是平移）：

```
X_world = t[0]·x + t[4]·y + t[8]·z  + t[12]
Y_world = t[1]·x + t[5]·y + t[9]·z  + t[13]
Z_world = t[2]·x + t[6]·y + t[10]·z + t[14]
朝向   = atan2(t[4], t[0]) + 槽位自身朝向
```

⚠️ **列主序还是行主序，不能靠猜** —— 本节用存档里的包围盒反证过（见第四节），**列主序正确**。

## 四、验证（三重，全部用真实存档数据）

### 4.1 slotId 逐个命中

存档里 station 198630 的 11 个 slotId，与公式给的"基址 + 序号"对照：

| 实测 slotId | 归属 | 校验 |
|---|---|---|
| 1002 | `main_building` k=2 | `1000+2` ✓ |
| 2010 | `hangar` k=10 | `2000 + (7 + 3×1)` = 2000+10 ✓（模板：`hangar1SlotId + 7 + 3*terminals`） |
| 8000 / 8050 | 第二跑道 / B 区站台 | 单例 ✓（两者同时存在 ⇒ 本场有双跑道） |
| 9001 / 9003 | `landing` | `9000+1`、`9000+3` ✓ |
| 70016 / 70019 / 70022 | 客站台 k=16/19/22 | `70000+k` ✓ |
| 80006 / 80013 | 货站台 k=6/13 | `80000+k` ✓ |

> **顺带一条重要事实**：模板 `createTemplateFn` 给的首个站台是 `terminal1SlotId + 6`，
> 但实测是 `+16/+19/+22` —— 说明**玩家后来改过站台位置**。
> ⇒ **绝不能用模板推布局，必须用实际的 slotId。**（这也解释了为什么"读模块对象"是前提）

### 4.2 模块盒 vs 引擎包围盒（**最硬的一条**）

把推导出的几何（地面矩形 ∪ 已放置模块盒 ∪ 跑道/滑行道）按 `transf` 旋转成 AABB，与引擎 `CONSTRUCTION` 的
`bounding_volume` 对账。判据：**引擎的框必须把推导几何整个包住**（模块模型/围栏比槽位盒大，所以引擎只会更大）。

| 机场 | 轴 | 推导范围 | 引擎 bbox | 残差 |
|---|---|---|---|---|
| 198630（45° 旋转） | x | 3757.9 … 4400.7 | 3757.9 … 4429.0 | **+0.0** / −28.3 |
| | y | −4681.1 … −4066.7 | −4681.1 … −4066.1 | **−0.0** / −0.5 |
| 237845（无旋转） | x | −3614.4 … −3034.4 | −3729.6 … −2919.2 | +115.2 / −115.2 |
| | y | −2048.9 … −1809.9 | −2159.7 … −1699.4 | +110.7 / −110.5 |

- 198630 **三面残差 0.0 m**，第四面（东侧）差 28 m = 降落方向灯模型的悬挑。
- 237845 只算了场地（它的模块清单没采到，见第五节）→ 场地外还有模块与灯架，故四面各余约 110 m。

**反证**：如果按"行主序"读 `transf`，198630 的 y 下界只能算到 −4645.8，**包不住引擎的 −4681.1** → 行主序排除。

### 4.3 y 符号（一个差点写错的坑）

`.con` 里 `modules1PosY = 0`、`modules1BackY = −110`，两者都叫"Pos/Back"，**传给 `MakeAllSlots` 的是 `BackY`**，
模块中心 = `−110 + 55 = **−55**`。若误用 `PosY` 会算成 `+55`，整体偏 110 m、且模块跑到场地矩形**外面**。
第二座机场（无旋转）的包围盒 y 下界 = **−110.66**（公式 −110）⇒ 直接钉死了这个符号。

## 六、"直接读模块对象里的坐标"这条路走不通（更正）

交接 4 与旧 skill 里写过一句"**不要依赖反解，直接读模块对象里的坐标**" —— **这句作废**：

- v3 探针已经实测：模块对象**恰好 4 个字段**（`metadata` / `name` / `updateScript` / `variant`），**没有任何坐标**。
- 官方文档也确认这 4 个字段就是全部，几何只在构建期的 `result.slots[]`。
- ⇒ **能拿到坐标的路只有两条**：① 复现 `.con` 公式（本文，纯静态）；② 读实体的 `MODEL_INSTANCE_LIST` 组件
  （`api.type` 定义 = "Contains all models rendered by the entity"，其中的 `ModelInstance` 带 `transf`），
  再按模型路径聚类回模块 —— **这条路有可行性但需另起一条探针验证**（模型没带 `tag`，得靠模型路径匹配）。
