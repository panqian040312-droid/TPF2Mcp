## 一、今天干成了什么（按主题）

### 1. 🔴 产业链数据链路 —— 字段语义实测锁定（今天最大的突破）

用户诉求：「选中某个产业 → 高亮上下游 + 物料流向 + 关联交通」，并补充
「货物最终送达城镇、在城镇消失」。

**核心认知：`SIM_CARGO.sourceEntity` 不是产业实体，是产业的库存(stock)**，
值等于 `SIM_BUILDING.stockList`（实测 **97/97 零误差**）。
`targetEntity` 分两类：**43/563 是产业的 stock**（厂→厂原料链）、**其余约 520 是城镇**（终端消费）。

| 弯路 | 结果 |
|---|---|
| 拿 cargo 的 id 去 `get_industry(id)` / `get_town(id)` | **全部 ENTITY_NOT_FOUND**（id 空间不同） |
| 拿旧产物 `demand-probe.json` 的 id 对照当前产业列表 | **0 命中** |
| ✅ 拿 `layer-industry.json` 的 **`stock_list`** 对照 | **97/97** |

🔴 **运行时 entity id 不能跨"取数时刻"交叉核对**，必须同一 tick 内取两边。
🔴 `cargoType` 官方标 int，但 `tostring` 出来是**可读名**（"FOOD"/"PLASTIC"/"CRUDE"）。
🔴 `api.engine.getEntity(edgeId,cargoType)` **不是按 id 取实体**；要用 `game.interface.getEntity(id)`。

详见 skill `tpf2-mod-bridge-ops/references/04-lines-and-frontend.md` 的「六之五」。

### 3. 航空调度机制 —— 摸清了（引擎 C++，lua 层零命中）

- `res/scripts/` 与 `base_config.lua` 里 runway/aircraft/landing **全部零命中** ⇒ 调度在引擎里。
- 官方手册（`linesvehicles.md`）：**飞机的"决定点"= 跑道末端**。
- 官方 API：`Aircraft.reservedLandingRunway`（bool，唯一 ⇒ 跑道独占预留）、
  `reservedTo`（预留到路径第几条边）、`aircraftMoveSystem.isReserved(edgeId)`（查某条跑道边是否被占）、
  `runwaySystem.getLandingNodeIdMap()`（**降落节点 → 可达车站**，实测各 128 条）。
- 社区指南印证用户的"盘旋很久"：**跑道 × 站台耦合** —— 站台不够 → 飞机落地出不去堵跑道 →
  跑道不释放 → 后续在空中盘旋。解法是加站台/备选站台。
- 🔴 **v2 探针失败的根因**：`isReserved` 等接口报 `expected userdata, received no value`，
  不是签名不对，是**传进去的 entity 是 nil**（`getEntity(id)` 取实体失败）。
  ✅ **正解 = 用 `forEach` 回调拿有效 userdata**。已写成 `route_probe.lua` v3。

## 六、本篇新增的环境坑

- **robocopy 三坑**：见 §一.6（`/MIR` 删本地配置 / 时间戳噪音 / `/NJS` 藏汇总）
- **bat 必须 CRLF + 纯 ASCII**（LF 会让 `goto :label` 失效；`chcp 936` 下中文注释易乱码）
- **Git-Bash 调 robocopy**：参数要用 `/E` 而非 `//E`，且带 `MSYS_NO_PATHCONV=1`
- **游戏没重启 = Lua 全部白改**：探针/采集器的"生效"判定**必须看产物内容**（note 版本号、新字段），
  不能只看文件 mtime —— 本篇 §二 就是这么查出来的
