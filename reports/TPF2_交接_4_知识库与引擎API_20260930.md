出处：`_digest\08`（api.type 全量精读，**尚未实测验证**）

| # | 现状（笨办法） | 应该改成 |
|---|---|---|
| 1 | 自己寻路，重建车辆/线路的实际走行路径 | 直接读 **`MovePath.path.edges`** —— 有序 `[{EdgeIdDir,…}]`，采样在途车辆聚合即可 |
| 2 | 按几何（距离/平行度）判单线复线 | 用 **`TransportNetwork.for`**（每条边的**对向车道首边索引**）—— 官方唯一直接暴露双向车道配对的字段 |
| 3 | 拿 `EdgeId` 只比 index | ⚠️ **`EdgeId = (TRANSPORT_NETWORK 实体, index)`**，index 只在网络内唯一 → **只比 index 会跨网络串线**（现存隐患） |
| 4 | 用"速度≈0"推断拥堵 | 用引擎现成 **`VehicleOrder.waitingForSpace` / `waitingForTrafficLight`** |

**另两条操作性收益**：
- **写命令有 34 条**（`api.cmd`，`make.*` 33 ＋ `sendCommand`），我们只用了极少数 ——
  含 `setGameSpeed` / `setCalendarSpeed` / `setDate` / `buyVehicle` / `replaceVehicle` / `sellVehicle` /
  `setLine` / `updateLine` / `buildProposal`（**唯一脚本化建拆基建入口，无回滚**）→ 可做对照实验。
- **`debugMode = true` → 模拟速度可达 32 倍**（常规上限 4）；`ModValidator 0.10.0` 可自动复核 mod 打包白名单。
- **`api.res` 的正确用法是"先 find 再 get"**：`get()` **只吃整数索引**，传字符串报 `expected number, received string`
  （我们踩过）；`getAll()` 返回的是「索引→文件名」映射，**不是资源本身**。

## 四、曲线半径 → 限速：官方公式（游戏手册里没有）

**出处**：`modding/tracksstreets.md:146–151`（**modding 文档，不是游戏手册**）

```lua
speedLimit  = 300.0 / 3.6        -- [m/s] 直段最高速
speedCoeffs = { .9, 15.0, .63 }  -- 曲线限速 = a * (radius + b) ^ c
```

> **曲线限速 = `0.9 × (radius + 15.0) ^ 0.63`**（m/s）｜直段 = `speedLimit`｜**桥另有独立限速，取 min**
> ⚠️ `speedCoeffs` 是**每类轨道自己的**参数（上面是标准轨道），换轨道类型要回查。

**实算对照（标准轨道，直段 300 km/h）**：

| 半径 | 曲线限速 | 占直段 |
|---|---|---|
| 44 m（吸附最小） | 42 km/h | 14% |
| 60 m（拖动最小） | 49 km/h | 16% |
| 100 m | 64 km/h | 21% |
| 200 m | 96 km/h | 32% |
| 300 m | 122 km/h | 40% |
| 500 m | 166 km/h | 55% |
| 1000 m | 254 km/h | 85% |
| ≥1308 m | 不再限制 | 100% |

⇒ **实用推论：车辆顶速 ≤ 120 km/h 时，半径 ≥ 294 m 的弯就不是瓶颈**（≤ 80 km/h 只需 ≥ 147 m）
→ **先比车辆顶速、再怀疑半径**，别一看弯道就把慢归因于曲线。

**同页还找到坡度与最小半径**（此前误以为"官方没给"）：
`minCurveRadiusBuild = 60.0` / `minCurveRadius = 44.0` [m]、
`maxSlopeBuild = 0.075`（**7.5%**）、`maxSlope = ×1.6`、`maxSlopeShape = ×1.25`。
⚠️ 属**标准轨道类型**的值，mod 可改，**不是引擎硬上限**。
