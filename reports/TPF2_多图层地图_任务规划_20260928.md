## 〇、先回答被问到的两件事

### 1. 「有没有合并进 mod 里面？」—— 没有，而且方向要掰正

现状是**三套东西各跑各的**：

| 角色 | 跑在哪 | 谁启动 | 干什么 |
|---|---|---|---|
| mod（Lua） | 游戏进程内 | 游戏启动时加载 | 读游戏数据、往 `bridge/` 写 JSON |
| MCP 服务 | WorkBuddy 托管的 stdio 进程 | WorkBuddy | 你让我发命令时用 |
| 地图服务 | 独立 Python 进程，HTTP:8765 | 你双击桌面的 bat | 后台每秒抽数据 + 切图块 + 给前端供页 |

**"合并进 mod"要拆成两半说：**

- ❌ **字面合并做不到**：mod 是游戏沙箱里的 Lua，没有网络、开不了端口、跑不了 Python。那两套 Python 服务塞不进去。
- ✅ **该合并的是「周期性取数」这个动作**，而且 mod 里**已经有现成模板**：

| 已有先例 | 位置 | 怎么自驱 |
|---|---|---|
| `heartbeat.json` | `runtime.lua:308` | 每个 tick 无条件写一次，地图服务靠读它判在线 |
| `demand-probe.json` | `collectors/demand_probe.lua` | 自己数 tick，`WRITE_EVERY_TICKS = 60` 写一次 |

**结论**：抢锁的根因不是"没合并"，而是**实时车辆层还在用命令拉**（服务端 `refresh_live()` 每 1.5 秒发一条 `get_operational_telemetry`）。改成 mod 自驱推送后，地图服务退化成"纯读文件 + 渲染"，锁争用基本消失。

## 二、三个必须先理顺的地基问题

这三个不修，图层加上去也是白加。

### 问题 1 · 地图数据落地目录错位（🔴 现在就是坏的）

| 位置 | 有 manifest / tiles / station-previews 吗 |
|---|---|
| 项目 `E:\workbody\TPF2Mcp\ui\rail-map\` | ❌ 只有 `rail-network-data.json` |
| staging `…\tpf2mcp_1\ui\rail-map\` | ✅ 全套（18:03 生成） |

原因：`start_rail_map.bat` 里加了 `--ui-directory "E:\workbody\TPF2Mcp\ui\rail-map"`（19:09 之后），把服务的**数据根目录**指到了项目目录，而 exporter 的输出也跟着走 `app.root`。但项目目录从来没有生成过 manifest 和图块 —— 地图数据还留在 staging。

**后果**：现在启动地图服务，index.html 会去项目目录找 `rail-network-manifest.js`，404，地图是空的。

**修法（二选一）**：
- **A（推荐）**：手动跑一次 exporter，输出到项目目录，之后数据就跟前端同目录了
- **B**：把 `--ui-directory` 去掉，接受"前端改完要同步到 staging"的旧流程

### 问题 2 · 实时层还在用命令拉（抢锁根源）

`serve-rail-map.py:848` 每 1.5 秒一条 `get_operational_telemetry("vehicles_live")`，信号每 300 秒一条。而 `BridgeClient.call()` 是**拿着锁等回包**的，地图服务导路网那次用 30 秒超时 → 你的 MCP 侧 15 秒必然抢不到。

**修法**：mod 自己在 tick 里按周期写 `operational-telemetry-vehicles_live.json`，服务端 `refresh_live()` 改成纯读文件。

### 问题 3 · 运行时分裂：代码都在项目里，跑的却是 staging 副本

用户 2026-09-28 20:43 澄清：「合并进 mod」指的是**合并进 `E:\workbody\TPF2Mcp` 这个项目仓库**，不是塞进游戏里的 Lua 沙箱。

按这个口径看，**代码其实一直就在项目里**（`tools/`、`ui/`、`mcp_server/`、`tpf2_mod/` 全在，git 管着）。真正的分裂在**运行时**：

| 层 | 代码在哪 | 运行时跑哪 | 能不能合 |
|---|---|---|---|
| Python（MCP 服务） | 项目 ✅ | ❌ staging 副本（`~/.workbuddy/mcp.json` 指向 staging） | ✅ **能合** |
| Python（地图服务） | 项目 ✅ | ❌ staging 副本（bat 跑 `%MODDIR%\mcp_server\start_ui.py`） | ✅ **能合** |
| 前端 `ui/rail-map/` | 项目 ✅ | 项目 ✅ | 已合 |
| 地图数据 | 项目 ✅ | 项目 ✅ | 已合（本次补齐） |
| `tools/` 脚本 | 项目 ✅ | 项目（手动跑） | 已合 |
| **Lua 资源 `res/` + `bridge/`** | 项目（只存源） | ❌ staging | ❌ **合不了** |

> Lua 合不了不是选择问题：TPF2 只从 Steam 的 mod 目录（`local/mods`、`workshop/content`、`staging_area`）加载脚本，你说的不算。
> 所以「改 Lua → 部署到 staging → 完全退出游戏再启动」这条链永远不会消失。

**切换方法（已实测，三步）**

第 1 步 —— `~/.workbuddy/mcp.json` 里 tpf2 这项，`args` 改指项目，并**加上 `env`**：

```json
{
  "mcpServers": {
    "tpf2": {
      "command": "C:\\Users\\RailG\\.workbuddy\\binaries\\python\\versions\\3.13.12\\python.exe",
      "args": ["E:\\workbody\\TPF2Mcp\\mcp_server\\start_server.py"],
      "env": {
        "TPF2_MCP_MOD_DIR": "C:\\Program Files (x86)\\Steam\\userdata\\1070536217\\1066780\\local\\staging_area\\tpf2mcp_1"
      }
    }
  }
}
```

🔴 **`env` 必须加**，否则服务起不来。2026-09-28 三组对照实测：

| 测试 | 结果 |
|---|---|
| A. staging 那份 `start_server.py` | ✅ 干净启动 |
| B. 项目那份，**不设** env | ❌ `FileNotFoundError: TPF2 MCP mod installation not found` |
| C. 项目那份，**显式**设 env 指 staging | ✅ 干净启动 |

原因两段：① `start_server.py` 只在**自己父目录**存在 `res/scripts/tpf2_mcp/runtime.lua` 时才自动设 `TPF2_MCP_MOD_DIR` —— 项目里 Lua 在 `tpf2_mod/res/…`，探测不到；② `config.py` 的自动探测只找 `local/mods` 与 `workshop/content`，**不找 `staging_area`**。

第 2 步 —— `start_rail_map.bat` 改跑项目的 `start_ui.py`，并补环境变量：

```bat
set "MODDIR=C:\Program Files (x86)\Steam\userdata\1070536217\1066780\local\staging_area\tpf2mcp_1"
set "PROJECT=E:\workbody\TPF2Mcp"
set "TPF2_MCP_MOD_DIR=%MODDIR%"
"%PY%" "%PROJECT%\mcp_server\start_ui.py"
```

（`--ui-directory` 可以去掉了 —— 跑项目那份时 `serve-rail-map.py` 的 `repository` 就是项目根，默认就指向项目 `ui/rail-map`。）

第 3 步 —— 重连 MCP（重启 WorkBuddy 或重新加载 MCP 配置）。

**收益**：改 Python 代码**立即生效**，不再需要「改项目 → 部署 staging → 重启服务」三步。staging 退化成纯部署产物，只有 Lua 需要同步。

**代价**：切换会让当前会话的 `mcp__tpf2__*` 工具断一次。
所以**建议先拿 v4 探针、再做切换** —— 一次只动一个变量。

## 五、需要你定的三件事

1. **多图层地图主要拿来干什么？**
   - 运营决策（看拥堵、客流、货流、产业分布）→ 优先阶段 3.3
   - 全局概览 / 欣赏（地形、道路、水体、城镇）→ 优先阶段 3.2
   - 两者都要 → 按上面的默认顺序

2. **图层要"叠加显示"还是"单选切换"？**
   - 叠加（勾选多层同时看）→ 前端工作量更大，要做绘制顺序和性能管理
   - 单选（一次一层）→ 简单，但没法看"铁路穿过哪些城镇"

3. **要不要保留 `--ui-directory` 指向项目目录？**
   - 保留（推荐）：前端改完立即生效，不用同步；但要跑一次 exporter 把数据补到项目目录
   - 去掉：回到"前端也跑 staging 副本"的旧流程

4. **什么时候把 Python 侧切到项目目录（问题 3）？**
   - 建议**先拿 v4 探针再切** —— 切换会断一次 `mcp__tpf2__*` 工具，两个一起做会分不清是谁的问题
