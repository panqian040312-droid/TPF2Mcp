## 四、实测出来的机制（迁移到新档直接可用）

### 4.1 运力公式（**精确成立，269/271 条线**）
```
line.rate(吞吐量，游戏原生 UI 的"吞吐量") = round(730.5 × 单车容量 ÷ 发车间隔)
```
- 730.5 = 2×365.25 → 引擎内部 1 年 = 730.5 个频率单位（出处：`config/base_config.lua` 的 `closureCountdownTimeSpan = 730.5*2000`）
- **`rate` 可由「容量+间隔」完全推出，不含任何需求信息** → 语义是「满载口径的理论年运力」
- ⚠ **rate 排名 ≠ 需求排名**（已证伪两次：rate 第 1 的 IS炼钢需求≈0；rate 第 1 的 YZ客运实载 68%）

### 4.2 真实客流**能拿到**（引擎接口，不是内存、不是存档）
```
api.engine.system.simPersonSystem.getSimPersonsForLine(line_id)
api.engine.system.simCargoSystem.getSimCargosForLine(line_id)
```
实体归属靠组件：`SIM_ENTITY_AT_VEHICLE.vehicle` = 在车上；`SIM_ENTITY_AT_TERMINAL.line/.arrivalTime` = 在站候车（可算等待时长）；`.lineStop0/.lineStop1` = OD。
mod 里已实现（`collectors/line_demand.lua`）→ 命令 `get_line_demand`。
另：存档里有 `__ug_game_info_passenger = 1594787`（全存档累计乘客人次）、cargo = 14523872。

### 4.3 车站承载人数（**权威源码**）
`res/scripts/modulesutil.lua:19` `getStationPoolCapacities()`
→ **车站承载人数 = Σ 该站所有模块的 `metadata.moreCapacity.passenger`**（货运站取 cargo）。
- 原版模块化车站 45 个模块，24 个提供容量：主站房 A/B/C = **100/150/200**（30,000）、**40/45/50**（20,000）、**20/25/30**（10,000）；侧房 = **80/100/150**（25,000）、**30/35/40**（15,000）、**10/15/20**（5,000）；货运版主站房 20/40/80、侧房 10/30/60
- **站台模块长度 = 40 m（宽 5 m；货运 10 m），造价 18,000** → 京广复兴号 430 m 需 **11 个模块**
- 站台/雨棚/楼梯/轨道模块**不提供容量**，容量只来自「主站房」「侧房」
- ⚠ `STATION_GROUP.capacity` 通过 API 仍是 nil → 站台容量读不到，只能由用户在游戏里读一次
- 解析脚本 `station_modules.py` → `ui/rail-map/station-module-catalog.json`

### 4.4 车站在站数据（探针带来的"以为读不到其实能读"路径）
- `station.cargoWaiting.PASSENGERS` → 每站实时候客
- `vehicle.cargoLoad.PASSENGERS` → 单车实际载客
- 车站实体可读：`itemsLoaded` / `itemsUnloaded`（累计上下客）/ `cargoWaiting` / `stations` / `position` / `name`
- ⚠ mod 作者当年因原生崩溃关闭了车站采样 → 接入这两条路径需谨慎测试
- ⚠ 实时帧（`vehicles_live`，每秒更新）**只有位置/速度/停站序/门/发车倒计时，无装载字段**

### 4.5 写操作链路（**正确用法，避免重踩**）
- 独立 `propose_operation` → `validate_operation` **必然失败**（`STALE_PROPOSAL`）：校验要求快照序列 == 提议时的序列，而每次观测都会推进序列（+1），提议永远追不上
- **正确路径是任务链路（原子的）**：`create_task(goal_type, goal, policy=MANUAL, max_steps=1, max_write_operations=1)` → `plan_task` → `approve_task_step` → `continue_task`
  （`continue_task` 内部：重新观测 → 序列变了则**免费重排** → 提议 → 执行 → 校验）
- 顺序注意：`approve_task_step` 在 `plan_task` **之前**调用会返回 `APPROVAL_NOT_APPLICABLE`
- goal_type / 字段：`SET_LINE_STOP_POLICY_GOAL`(line_id/stop_index/load_mode/min/max) / `BUY_VEHICLE_GOAL`(depot_id, source_vehicle_id) / `ASSIGN_VEHICLE_TO_LINE_GOAL`(vehicle_id, line_id) / `SELL_VEHICLE_GOAL`(confirmation="SELL_VEHICLE:<id>") / `HOLD_VEHICLE_AT_TERMINAL_GOAL`(vehicle_id, max_hold_seconds 10..600)
- 能力清单里的 `live_write_enabled` / `global_write_default` 是 `server.py` 的**硬编码 false**，不反映 Lua 真实开关，别拿它判断
- 写开关文件：`<mod>/res/scripts/tpf2_mcp/local_config.lua`
  ```lua
  return { allow_write_operations = true,
           allowed_operations = { SET_LINE_STOP_POLICY = true } }   -- 按操作名索引的表，不是字符串数组！
  ```
  - 写成 `{ "SET_LINE_STOP_POLICY" }` 会被拒为 `UNSUPPORTED_OPERATION`
  - 两个拒绝码：`WRITE_DISABLED` = 总开关关；`UNSUPPORTED_OPERATION` = 不在白名单
  - **config 只在游戏启动时读 → 改完必须完全重启游戏**
  - ⚠ 该文件只存在于 staging 副本；`_tmpdb\local_config.lua` 里有副本
  - **当前白名单只开了 `SET_LINE_STOP_POLICY`**（新档 9-28 未改）
- `SET_LINE_STOPS` 只能替换成**同长度**的停站向量，加不了站
- `HOLD_VEHICLE_AT_TERMINAL` 只能作用于 `raw_state=2`（在终点站停着）的车
- **Mod 无建造类操作**（铺侧线/加站台/改限速/改信号都做不到）；`REMOVE_VEHICLE_FROM_LINE` 不可用（减车只能 `SELL_VEHICLE` 卖车）

### 4.6 成本
- 车辆成本**在 `.mdl` 的 metadata，不在游戏 API**（API 的 maintenance/revenue/profit 全返回 nil）
  - `cost = { price, priceScale }`、`maintenance = { lifespan, runningCosts, runningCostScale }`
  - **`price = -1` = 游戏自动定价**（原版车也全是 -1，**不是免费！**）；只有显式 `price = 0` / `priceScale = 0` 才是零购置成本
  - `runningCostScale < 1` = 打折；`= 0` 才是免费运行
  - 旧档实测：零购置成本 1 辆（JI线路，mod 2819774551）；运行成本 6 折 16 辆（悬挂单轨）；**无免费运行车辆**
  - 解析坑：复兴号把成本写成 **Lua 变量**（`local trainCostPrice = 6.142857143e+06`）→ 只认字面数字的解析器会误判成"自动定价"
    - 修正后：CR400AF 每节 price 6,142,857.143、runningCosts 6,142.86/年；8 节 ≈ 49,142,857，按 mod 自述「1 单位 = 0.5 美元」≈ **$24,571,429**，与 mod 说明 "about $24,600,000" 对上
  - "运营费用 0" 是**显示舍入**：财务图以百万为刻度，$24,571 显示成 0.0 M
  - 脚本：`scan_workshop_costs.py`、`resolve_vehicle_cost.py`、`cost_per_train.py`、`build_cost_profile.py`
- **轨道与车站维护费 API 读不到** → 基建才是长期成本大头
- **"不持续亏钱"的唯一可靠检查**：分线盈亏读不到 → 每次改动后看游戏财务页的营运成本曲线与余额斜率
